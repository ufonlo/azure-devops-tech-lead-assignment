# CTO summary

The proposal uses a small managed Azure platform: Container Apps, Container Registry, Key Vault and Log Analytics. One Terraform module defines the platform, while development and production have separate state, identities and lifecycles. Development changes or credentials therefore cannot silently cross into production. The Free Trial permits one Container Apps environment globally, so development serves the API and production currently has supporting resources but no runtime.

GitHub Actions uses workload identity federation, with no long-lived Azure credential in GitHub. Infrastructure pull requests are formatted, validated and security-scanned, with separate development and production plans shown for review. After merge, the pipeline applies the exact saved development plan, then prepares production. Production verifies the saved plan checksum and requires approval through a protected GitHub environment before applying it. This path runs end to end today; production will serve traffic after moving to the target separate subscription and enabling its runtime.

Container Apps was selected over AKS because the requirement is one containerized API rather than a Kubernetes platform. It supplies managed ingress, revisions, autoscaling and scale-to-zero with less cost and operational work for a small team. AKS remains an option when Kubernetes-specific requirements exist.

The main residual risks are bootstrap privilege, public endpoints, untested application health behavior and incomplete disaster-recovery requirements. Next work is immutable image promotion, smoke tests, alerting, private networking where justified, and a rollback game day. AI accelerated drafting, but deterministic validation, human plan review and explicit data-handling rules remain mandatory.
